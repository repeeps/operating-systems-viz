# 운영체제, 눈으로 보기

컴퓨터를 떠받치는 **운영체제(OS)**의 핵심 직관 — 프로세스·스케줄링·가상 메모리·파일·입출력 — 을, 수식·코드 없이 **움직이는 그림과 인터랙션**으로 익히는 비영리 학습 자료입니다. 0번 입문 + 18챕터.

> 특정 OS 강좌가 아니라 **멘탈 모델**이에요 — 커널이 한 CPU를 여러 프로세스에 번갈아 주고(스케줄링), 가상 주소로 각자에게 큰 개인 메모리를 그려주고(페이징), 흩어진 디스크 블록을 하나의 파일로 보이게 하는 과정을 **직접 만지며** 봐요.

## 어떻게 보나

별도 빌드·설치가 없습니다. `index.html`을 브라우저로 열면 됩니다. 모든 스케줄링 간트·페이지 폴트·교체 정책·적중률은 브라우저에서 **실시간 계산**됩니다.

## 구조

처음이라면 **0번부터 순서대로**. 척추는 **보호 경계(A) → CPU 가상화(B) → 메모리 가상화(C) → 저장(D) → 종합(E)**.

- **0번 — 한 대로 여럿을**: 한 컴퓨터를 여럿이 혼자 쓰는 듯 보이게 하는 세 가지 착각(CPU·메모리·파일) · 보호·용어표 · 코스맵
- **PART A · 보호의 경계**
  - 01 OS의 역할 (자원 관리자 + 마술사)
  - 02 커널 모드 vs 유저 모드 (특권의 벽 · 모드 비트)
  - 03 커널로 들어가는 세 문 (시스템콜 · 인터럽트 · 예외/폴트)
- **PART B · CPU 가상화 — 프로세스와 스케줄링** — 기둥①
  - 04 프로세스란 무엇인가 (주소 공간 + PCB)
  - 05 프로세스의 탄생 (복제 → 갈아끼우기 · 프로세스 나무)
  - 06 문맥 전환 (저장·복원 · 타이머 인터럽트 선점)
  - 07 스케줄링 ① 누가 먼저 (FCFS · SJF · 호위 효과)
  - 08 스케줄링 ② 공정하게 (라운드 로빈 · 시간 조각 · 우선순위)
- **PART C · 메모리 가상화 — 메모리의 마법** — 기둥②
  - 09 왜 가상 메모리인가 (격리는 항상 · 큰 척하기는 필요할 때)
  - 10 페이지와 페이지 테이블 (칸 단위 매핑 · 권한 비트)
  - 11 번역을 빠르게 — TLB (지역성과 적중률)
  - 12 요구 페이징 (페이지 폴트 = 정상 신호)
  - 13 페이지 교체 (FIFO · LRU · 최적 · 스래싱)
- **PART D · 파일과 저장**
  - 14 파일은 어떻게 저장되나 (아이노드 · 디렉터리)
  - 15 디스크 위의 살림 배치 (구역 · 가용 지도 · 지역성)
  - 16 느린 장치와 대화하기 (폴링 vs 인터럽트 방식 I/O)
- **PART E · 큰 그림**
  - 17 한 줄의 여정 (파일 읽기가 모든 조각을 거치는 합주)
  - 18 여기서 더 나아가면 (동시성·IPC·멀티코어·가상화·보안)

두 기둥은 **CPU 가상화(B)** 와 **메모리 가상화(C)**. 나머지는 둘을 받치고 잇는 장치예요. (반복 테마: **캐싱** — 느린 층을 빠른 층으로 가리기.)

## 기술

- 순수 정적 HTML + JavaScript (의존성·빌드 없음)
- 공통 엔진 `shared/lib.js`(VZ 코어 + 스텝 플레이어 VZ.AL + heatColor) + `shared/lib-os.js`(운영체제 도메인 엔진 VZ.OS: 프로세스 박스·레디 큐·CPU 간트·PCB·커널/유저 경계·주소 공간·페이지 테이블·물리 프레임·TLB·디스크·아이노드·블록) — 모두 순수 함수(상태 → SVG)
- 다크 테마 `shared/theme.css`
